# ゲーム内ロジック

設定ファイルを適切に調整するために知っておくと役立つ、基本的なゲームルールをまとめています。Javaの実装(クラス名・SQLなど)ではなく、「何がどう決まるか」という仕組みの話です。

## レベルとステータス成長

- HP・SP・攻撃力・防御力は指数的に成長します: `そのレベルの値 = base × growth-rate ^ (レベル-1)`。`base` は [`config.yml: status.growth`](config-guide.md#status)、`growth-rate` は [`config.yml: stat-scaling.growth-rate`](config-guide.md#stat-scaling) の値です。`growth-rate`が1.045なら「1レベルごとに+4.5%」が複利で効いていきます。
- SPD(移動速度)だけは指数ではなく、`base + per-level × (レベル-1)` の一定量ずつの成長です。
- CRT(会心率)・CRT_DMG(会心ダメージ)はレベルでは変化しません。レリック・アクセサリーのボーナスでのみ上がります。

## ダメージの計算順序

1つの攻撃のダメージは、次の順番で決まります(戦闘ダメージ計算式の詳細は [DAMAGE_FORMULA.md](https://github.com/orelia-mc/orelia-core/blob/main/DAMAGE_FORMULA.md) も参照)。

1. **基礎攻撃力** — 武器の攻撃力 × 武器レベルボーナス × 強化ボーナス
2. **ATK%** — 攻撃側のステータスによる補正
3. **DEF(防御力)による軽減** — 受け側の防御力で減衰
4. **会心判定** — 会心率で判定し、当たれば会心ダメージ倍率を掛ける
5. **属性弱点** — 攻撃側武器の属性がモンスターの弱点属性(`monsters.yml`/`bosses.yml`の`weakness`)と一致すれば、さらに固定 ×1.5

この順序は近接・遠距離・スキル・モンスターの通常攻撃すべてで共通です。モンスター/ボスの「アビリティ」攻撃(`monsters.yml`/`bosses.yml`の`abilities`)も同じパイプラインを通ります — `damage:` の値はそのモンスター自身の(レベルスケール後の)攻撃力に対する**倍率**であって、固定ダメージ量ではありません。

## スケール済みHP(バニラ体力との対応)

プレイヤー・モンスターの「本当のHP」(数百〜数百万になり得る)は、バニラのハート表示(最大20)とは別の内部値として管理されています。バニラの体力は常にその内部値と同じ割合になるよう自動的に同期されます。`config.yml: combat.scaled-health.vanilla-cap` はモンスターのバニラ体力の上限(見た目の被弾演出の大きさに影響するだけで、実際のHP・死亡判定には影響しません)。

## モンスターのレベルスケーリング

- モンスターは基本的に `monsters.yml` に書かれたHP/攻撃力/防御力のテンプレート値のまま湧きます。
- [`/oladmin spawnpoint add`](core-commands.md#spawnpoint) で **目安レベル** を指定すると、そのスポーンポイントから湧くモンスターは `config.yml: stat-scaling.growth-rate` に従ってプレイヤーと同じ曲線でステータスがスケールし、さらに `config.yml: monster.target-level-bonus` の追加倍率が乗ります(モンスター専用の底上げで、素のプレイヤー成長曲線だけだと高レベル帯でモンスターが脆くなりすぎるための調整です)。
- 目安レベルを指定しなかった(または1のままの)スポーンポイントは、従来どおりテンプレート値のまま湧きます。
- ダンジョン産のモンスター/ボスは、後述の「ダンジョンの難易度」がそのままこの目安レベルとして使われます。

## ダンジョンのロジック

### 開放・アリーナ・同時挑戦数

- ダンジョンは `dungeons.yml` の `arenas:` にリストした物理座標の数だけ、**同時に挑戦できるパーティー数**が決まります(1アリーナ=1同時進行枠)。空きアリーナがなければ挑戦は拒否されます。
- プレイヤーは管理者が [`/oladmin dungeonblock set`](core-commands.md#dungeonblock) で登録したブロックを右クリックすると、そのダンジョンを「発見」します(プレイヤーごとに永続保存)。挑戦できるのは発見済みのダンジョンのみで、**チェックはパーティーリーダーに対してのみ**行われます(リーダーが発見していれば、未発見のメンバーも同行できます)。

### 難易度とスケーリング

- 難易度は固定ティア `5 / 10 / 15 / 20 / 30 / 40 / 50 / 60 / 70 / 80 / 90 / 100` から、**挑戦者自身のキャラクターレベル以下**のものだけを選べます。
- 選んだ難易度の数値は、そのままダンジョン内の敵・ボスの「目安レベル」として使われます(上記「モンスターのレベルスケーリング」と同じ計算式)。
- 選べるティアが1つもない場合(レベルが低すぎる場合)は「通常」= スケーリングなし(`monsters.yml`のテンプレート値のまま)になります。

### 挑戦の流れ

1. 難易度を選んだ瞬間にアリーナが確保され、以後の「満員」判定に即座に反映されます(実際のテレポートは後述のカウントダウンの後)。
2. 数秒のカウントダウン(Title表示)の後、パーティー全員がテレポートされ、敵とボス(いれば)が一斉に湧きます。カウントダウン中に全員がログアウトすると予約は自動的に解放されます。
3. `dungeons.yml` の `enemies:` に列挙した数の敵と、`boss-id`(あれば)を制限時間内(`time-limit-seconds`)に全滅させればクリアです。
4. クリア時: `reward-exp`/`reward-money` を獲得し、ボスがいるダンジョンなら [`config.yml: dungeon.relic-drop-min/max`](config-guide.md#quest-dungeon-party-friend-guild-mail-auction-trade) の個数のレリックがメンバーそれぞれにドロップします。
5. 制限時間切れは報酬なしで強制退出、`/ol dungeon retire` でいつでも自主離脱できます(いずれも発見状態そのものは失われません)。

### パーティー人数の制約

`dungeons.yml` の `min-party-size`/`max-party-size` の範囲外の人数では開始できません(ソロ専用ダンジョンは両方1、レイドは`min-party-size`を高めに設定するなど)。

## クエストの進行判定

`COLLECT_ITEM`/`DELIVER_ITEM`/`REACH_LOCATION` タイプの目標は、[`config.yml: quest.objective-check-period-ticks`](config-guide.md#quest-dungeon-party-friend-guild-mail-auction-trade)(既定40 tick=2秒)ごとに、オンラインプレイヤー全員に対して再チェックされます。`KILL_MONSTER`/`KILL_BOSS`/`TALK_NPC`/`CLEAR_DUNGEON` はイベント発生時(討伐・会話・クリア時)に即座に進行します。

## 武器の強化とレベルの違い

- **強化**(NPC経由、無制限)は基礎攻撃力に+10%ずつを掛けます。
- **武器レベル**は `config.yml: weapon-level` の設定に従い、プレイヤーのキャラクターレベルに応じた上限まで上げられます(`initial-cap`未満のレベル帯は`initial-cap`が上限、`tier-step`以上では`floor(プレイヤーレベル / tier-step) × tier-step`が上限)。攻撃力への影響は`attack-power-factor`(1レベルごとの倍率)で決まります。

両者は独立して積み重なり、どちらも武器そのもの(プレイヤーではなく)に紐づきます。
